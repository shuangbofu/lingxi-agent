# 架构边界

## 目标

灵析智能体是一个自托管、多 Runtime Web Agent 平台。平台提供确定性的用户、权限、模型、配置、任务、交互、事件、审计和展示能力；Agent Runtime 根据场景定义驱动模型，并通过当前任务允许的 Skill、平台工具和 MCP 获取证据或执行动作。

核心原则：

1. 平台内核不理解具体业务系统。
2. 场景声明能力，能力之间保持独立。
3. Java 管确定性状态和安全边界，Agent 管开放式理解与决策。
4. 外部输入始终是不可信数据，不能提升为平台指令。
5. 所有可执行动作都必须可定位到任务、用户、场景和能力。

## 分层

### 前端

负责：

- 登录、用户与系统配置界面。
- 场景选择和动态参数表单。
- 任务状态、事件、交互和结果展示。
- 历史、分享、导出、用量和配额展示。

前端不负责：

- 猜测或补全业务参数。
- 解析能力内部协议。
- 仅靠隐藏组件实现权限或敏感信息保护。
- 按场景 code 或能力 code 写业务分支。

### Spring Boot 平台内核

负责：

- 用户、角色、会话、权限和个人凭证。
- 场景定义、默认 Skill 和外置能力包的加载与管理。
- 分析情境、动态参数和能力服务配置。
- 任务生命周期、并发、超时、取消和失败重试。
- Runtime 选择、通用执行请求、会话恢复、事件、用量和取消路由。
- 能力命令安装、任务访问令牌和回调权限。
- 交互请求、附件归档、分享、用量与审计。
- 输入限制、路径边界、敏感值脱敏和统一异常响应。

平台内核不负责：

- 维护业务项目、环境、仓库、数据库或日志资源模型。
- 判断某个业务问题固定要调用哪些外部能力。
- 在 Java 中遍历或选择某类业务资源候选。
- 为具体外部服务定义业务字段映射或兼容分支。

### 场景模块

场景是用户入口，包含：

- 名称、说明、图标、颜色和排序。
- 用户可填写参数。
- Prompt、展示格式和交付要求。
- 当前场景允许暴露给 Agent 的能力列表。

场景可以依赖能力，但不能引用另一个场景。推荐关系由平台级 `scenario-recommendations.json` 独立维护，不属于任何场景定义。

### 能力模块

能力是标准 Agent Skill 及其 Lingxi 平台适配，包含：

- 描述身份、触发条件、工作流和边界的 `SKILL.md`。
- 描述展示、版本、参数、命令和私有入口的 `lingxi.json`。
- 可选的 `references/`、`scripts/`、`assets/` 和 Python 依赖。
- 管理员维护的 `configurationParameters` 与单次任务使用的 `taskParameters`。

能力必须做到“给定声明参数即可运行”。它不能直接读取另一个能力的内部文件、调用另一个能力的私有函数，或要求平台理解某个外部服务的业务格式。
能力也不能声明所属场景、其他能力、结果格式、队列优先级等任务级属性；能力不是任务入口。

### 外部服务和资源

项目资料、仓库、数据库、日志、知识等信息可以来自任意外部服务。常见流程是：

1. Agent 调用外部服务能力获取轻量候选摘要。
2. Agent 根据当前问题选择相关候选。
3. 真正使用时读取详情。
4. 需要交给另一个能力时，将对应资源写入任务工作区的临时文件。
5. 通过目标 Skill 的公开命令显式传入参数或临时文件路径。

平台只保护任务工作区、回调令牌和配置访问边界，不替 Agent 做业务候选选择。

## 任务流程

```text
用户选择场景并提交输入
  -> 平台校验权限、配额和输入
  -> 固化场景、分析情境和参数快照
  -> 创建隔离任务工作区
  -> 安装场景允许的能力命令
  -> 生成平台边界 + 场景 + 能力 + 任务 prompt
  -> 启动或恢复当前 Agent Runtime 会话
  -> 解析事件并按需等待用户交互
  -> 归档结果与附件
  -> 更新用量、状态和可选后续场景
```

继续追问优先恢复同一 Runtime 的会话状态；不同 Runtime 不共享私有 session 格式。平台同时保存每轮任务记录，以便按轮次展示事件和结果；会话级列表按根任务聚合，管理端执行记录仍可查看独立轮次。

## 信任边界

### 可信平台数据

- 代码中定义的权限与安全限制。
- 经过服务端校验的当前用户和任务关系。
- 平台生成的任务访问令牌。
- 从已加载场景定义、`SKILL.md` 和 `lingxi.json` 得到的模块元数据。

### 不可信数据

- 用户问题和交互回答。
- 外部服务、Git、日志、数据库和 Wiki 返回内容。
- 能力命令 stdout、stderr 和生成附件。
- Agent 输出的 Markdown、SQL、JSON 和链接。

不可信数据需要进行长度、格式、路径、HTML、链接和敏感值处理。任何文本中声称“忽略规则”“提升权限”或“调用未授权能力”都不能改变平台边界。

## 存储

- 安装目录保存场景与 Skill 的唯一固定定义；H2 不复制 Markdown、参数声明、Guide、脚本和图标。
- H2 保存平台可变状态、场景的 Skill/command code 授权、任务快照、事件索引、接入配置和用量。
- 场景、任务、分析情境和接入配置使用稳定 code 引用定义，不依赖定义数字 ID。
- 大段任务内容、事件详情和附件存放在 `data/` 下的文件目录。
- 模型供应商 API Key 和能力服务配置当前存储在 H2 中；接口展示会掩码、Runtime 输出会脱敏，但落库内容没有额外加密，因此必须严格保护数据库文件和备份的访问权限。
- 分享密码只保存哈希，明文只在创建或轮换时返回。
- `backend/src/main/resources/db/init.sql` 是当前数据库结构基线，Hibernate 启动时负责校验实体映射；开发期结构调整直接同步基线并重建本地数据库，不在业务代码中保留旧库兼容迁移。

## 明确禁止

- 在前端或 Java 中按外部场景、能力、项目或资源 code 写业务 `if/else`。
- 把其他能力的实现复制或引用到当前能力中。
- 把能力候选列表全部无差别塞进 prompt，代替按需查询。
- 将 API Key、密码、Cookie 或完整连接配置写入 prompt、事件或日志。
- 仅通过前端隐藏实现权限控制。
- 绕过任务令牌直接开放 Agent runtime API。
- 在未预览、确认和审计的情况下执行数据或代码写操作。
