# JDBC 只读查询

这个能力用于执行只读结构化数据查询，适合确认真实数据、数量、状态和查询结果。

## 能力边界

- 只允许读取数据，禁止 DDL、DML、存储过程、函数调用和任何写入行为。
- 查询必须服务于当前任务目标，不做无关的数据浏览。
- 查询失败时根据结构化错误判断能否在不改变查询目标的前提下修正；可明确修正时只重试失败语句，无法可靠修正时再说明错误和未完成原因。
- 涉及敏感字段时只返回完成判断所需的最小字段集合。

当任务结论依赖“当前数据事实”时使用它；如果只需要理解代码、文档或日志，不要为了补充材料而查询数据库。

执行查询时只提交 SELECT 或 WITH 语句。单次 `jdbc query` 调用支持 1 到 5 条只读语句，语句之间用英文分号分隔；工具会逐条执行并在 `results` 中按顺序返回每条结果。不要因为有多条 SELECT/WITH 就拆成多次调用，除非超过 5 条、需要分阶段使用上一条结果，或某条查询失败后需要单独重试。

查询失败时，可明确修正就只重试失败语句；无法可靠修正再说明原因，不要重复执行原 SQL。

能力不会自动寻找数据源，必须由调用者显式传入数据源配置文件。完整命令签名如下，`--sql` 和 `--sql-file` 二选一，查询理由较长时使用 `--reason-file`：

```bash
jdbc query --config-file /path/datasource.json (--sql 'select ...; select ...' | --sql-file /path/query.sql) [--reason 说明 | --reason-file /path/reason.txt]
```

包含中文、复杂引号、较长 SQL 或多条语句时，优先写入 UTF-8 临时文件再用 `--sql-file`：

配置文件应是 JSON 对象，至少包含 `url`、`username`、`password` 等连接字段。这个能力只负责按入参执行只读查询，不关心配置来自哪里。

如果场景已经提供可复用查询或明确查询口径，直接按场景口径执行查询；不要因为存在这个能力就主动扩展无关的数据浏览。
